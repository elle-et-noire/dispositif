# [Dispositif](https://elle-et-noire.github.io/dispositif/)

Astroベースの記事サイトです。記事はビルド時にMarkdownからHTMLへ変換し、数式はMathJax v4のCHTMLとして出力します。ブラウザ側ではMathJaxを実行せず、数式フォントも同一オリジンから配信します。支援技術には、各数式をTeXのソースで読ませます（`role="img"` と `aria-label`。理由は `docs/math-accessibility.md`）。

## 構成

```text
/
├── docs/
│   ├── math-accessibility.md             # 数式の読み上げ方式の決定記録
│   └── column-preload-investigation.md  # 記事を開くまでの時間の調査記録
├── lib/                    # 記事取得、Markdown前処理、MathJax変換、単体テスト（*.test.ts）
├── post/                   # Markdown記事
├── public/
│   └── fonts/mjx/          # predev / prebuildで生成
├── scripts/
│   ├── copy-math-fonts.mjs
│   └── measure-article-open.mjs  # 記事を開くまでの時間の計測
├── src/
│   ├── components/
│   ├── icons/              # 段組み切り替えアイコン
│   ├── layouts/
│   ├── pages/
│   │   ├── index.astro
│   │   └── [slug].astro
│   ├── scripts/            # 段組み、数式フォントの先読み、背景の一覧
│   └── styles/             # globals.css、column-layout.css
└── tests/                  # ブラウザテスト（*.browser.test.mjs）
```

今後の予定と残っている課題は `ROADMAP.md` にまとめています。

## コマンド

```sh
npm install
npm run dev -- --background
npm run build
npm run astro -- check
```

バックグラウンドの開発サーバーは次のコマンドで管理できます。

```sh
npx astro dev status
npx astro dev logs
npx astro dev stop
```

数式フォントは `predev` / `prebuild` の `scripts/copy-math-fonts.mjs` で用意します。起動中の開発サーバーの配信を維持するため、フォントディレクトリは削除せず、変更のないファイルも書き直しません。`tests/math-fonts.browser.test.mjs` は、準備処理の再実行後も全フォントを配信でき、1段・n段・記事遷移後にも数式フォントを読み込めることを確認します。

## 記事の段組み

1段・n段とも段組み切り替えアイコンで直接切り替えます。アイコンの編集元は `src/icons/single-column.svg` と `src/icons/multi-column.svg` です。ファイルの変更はAstro経由で画面へ直接反映されます。アイコンは切り替え先の1段／複数段を枠の分割で示し、閉じるボタンと同じ30px・線幅2px・色でそろえます。読み上げ用の名前と押下状態、切り替え先を示すツールチップも付けます。1段では記事右上、n段では上部目次の右側に置きます。段組み用の設定パネルや先頭・末尾へのボタンは設けず、Home / Endで移動します。1段の記事カードの配置を保ち、本文と右側の目次の間に32pxの間隔を設けます。閉じる・段切り替えボタンを目次の上に置き、まとめて追従させて重なりを防ぎます。狭い画面ではモバイル目次を使います。切り替え時は本文の要素とその中の位置を基準に、幅の変化をまたいで同じ箇所の近くを表示します。記事内リンクや直接のハッシュ変更も含め、ブラウザー履歴の読書位置と折りたたみの開閉状態は項目ごとに保持し、ページを離れるときに `sessionStorage` に最大100件保存します。復帰時は開閉状態を本文の計測と位置復元より先に適用します。モードの選択は `localStorage` に保存します。未選択時と保存値が不正なときは、画面幅にかかわらず1段です（`src/scripts/column-preference.ts`）。記事のURLに `?columns=multi` または `?columns=single` を付けると、保存された選択より優先してそのモードで開きます（例: `/dispositif/symmetric-polynomial/?columns=multi#見出しid`）。この指定は保存せず、URLも書き換えません。Astroのルーターはクエリが変わると戻る・進むを別ページへの遷移として扱うためです。その代わり、指定付きで開いた後に切り替えた場合は、再読み込みや戻る・進むでその履歴項目に記録した切り替え後のモードを使います。`?columns=` 付きのURLも `rel="canonical"` はクエリなしのURLです。`tests/column-url.browser.test.mjs` で確認します。JavaScript無効時と印刷時は通常のレイアウトです。

1段表示では見出しを縦に並べた目次を本文右側に常時表示し、本文のスクロールに追従します。画面幅768px未満では記事右上の矢印で同じ縦並びリストを開閉します。n段表示では見出しを横書きで上部に横一列へ並べ、折りたたまず常時表示します。収まらない分は横スクロールバー・タッチ操作・マウスホイールで移動でき、長い見出しも省略せず一行で表示します。見出しの選択・外側のクリック・Escでもn段の目次は開いたままです。どちらの目次も読書中の見出しを強調して表示範囲に収めます。上部の目次は3pxの細いスクロールバーをヘッダー下端に余白なしで配置し、ホバー・フォーカス時に少し濃くします。標準の太さ指定しか使えないブラウザーではthinを使います。目次と切替ボタンは高さ3.5remのヘッダに収まり、目次内の移動で本文の配置や読書位置は変わりません。1段表示の折りたたみ目次は見出しの選択・外側のクリック・Escで閉じます。JavaScript無効時も1段表示の目次とリンクを利用できます。記事一覧へは右上の閉じるボタン（1段の広い画面ではヘッダの「記事一覧」も）で戻ります。紙面の外の背景をクリックしても戻れますが、背景のリンク（`.cl-dismiss`）はポインター専用で、Tab移動と読み上げの対象から外しています。

段幅と間隔は `src/styles/column-layout.css` の CSS 変数で調整できます。

```css
:root {
  --cl-column-width: min(38em, calc(100vw - 2rem));
  --cl-gap: 1rem;
  --cl-edge-space: 1rem;
  --cl-column-padding: clamp(1rem, 2vw, 1.5rem);
  --cl-reader-space: 1rem;
  --cl-surface: #f8f8f8;
  --cl-ink: #324e73;
  --cl-scrollbar-size: 8px;
}
```

`ColumnLayout.astro` と `src/scripts/column-layout.ts` が全記事を拡張します。各段の表示枠はヘッダと上下の余白を除いた読書領域と同じ高さで固定します。縦にスクロールすると枠はその場に残り、全段の本文が一斉に上へ流れます。段間の本文の重なりは0固定です。

段の左右には16〜24px、記事冒頭には同じ量の余白を設けます。段幅は余白を含む幅で、元本文と複製に同じ余白を適用して組版・計測を一致させます。本文の外周余白は `--cl-edge-space`（既定1rem）で指定し、スクロール面の先頭と末尾に置きます。横移動に合わせて余白も画面外へ流れ、本文は画面端まで表示できます。縦横とも本文自身の標準スクロールバーを使い、別要素のバーや位置同期処理は設けません。1段表示では、画面全体を覆う透明な記事用スクロール領域自身の標準バーを同じ太さ・色・矢印で表示します。背景の一覧・ヘッダー・透かしはその領域の外に置き、バーの透明なトラック越しにも背景がそのまま見える構造にします。記事ページの文書自体はスクロールさせず、バー用の代理要素や位置同期処理は使いません。印刷時は通常の文書フローに戻します。対応ブラウザーでは8pxとし、それ以外は標準のthin指定に従います。狭い画面でも両端の余白を含めて1段が収まるよう段幅を調整します。段間・ヘッダー直下・外周の余白はすべて既定16pxにそろえ、その内側の表示高さをHとします。各段の上下端で本文を隠す余白は追加せず、段の連続性を維持します。これらの余白はn段モードだけに適用します。

段は左右へ仮想的に続き、初期表示の段番号を0、左隣を−1、−2…とします。高さをH、段の横の周期をPとすると、段kの表示位置は t = k × H + y です。初期状態は段0が左端です。Hだけ縦に読み進めて1段左へ移ると同じ本文位置に戻ります。

本文の先頭・末尾では部分段を許します。末尾の部分段は上端、先頭の部分段は下端を他の段にそろえ、本文がない部分では白い面と文字を同じ範囲で切り抜きます。背景面は本文とは別の要素にし、座標変更が数式全体のスタイル再計算へ波及しないようにしています。画面より短い記事は、本文の高さの1段だけを上揃えで表示します。

通常の横操作では、実際に本文が残る先頭段が左端、末尾段が右端にそろう位置まで移動できます。外側に空白を作るためだけの横移動はできません。縦操作では、横位置を固定したまま端の部分段が完全に消える位置まで進め、最大1段分の外側余白を作れます。その状態から横へ戻すと、縦位置を保ったまま連続的に内側へ移動でき、余白を増やす方向へは動けません。途中で縦位置が変わっても、横位置を通常範囲へ自動で戻しません。この制限は現在の座標から決め、到達経路を示すフラグは持ちません。狭い画面でも部分段を横から読め、縦位置を固定した横操作だけで本文全体を読めます。記事全体が画面幅より短い場合は先頭側にそろえ、1画面の高さ以下の記事は1段に固定します。縦操作では横位置を、横操作では縦位置を変えません。上下端での自動横誘導は行わず、上下の停止位置にも重なり分の追加余白を設けません。記事の先頭・末尾が基準段の上端・下端にそろう位置で止め、隣の重複だけの部分段はその時点で消えます。

端の部分段では、スクロール面と一緒に動くレールの切り抜きを白い面に合わせます。固定枠そのものには切り抜きを設定せず、本文の組版を保持します。原点変更の補助座標はCSS変数ではなくdata属性に記録し、数式ツリーへの不要なスタイル再計算を避けます。

同じ論理座標なら、到達経路によらず本文と白い面は同じ配置になります。縦操作が止まった画面を常に同じ配置へ吸着させる処理はありません。Homeは先頭段を左端、Endは末尾段を右端にそろえ、外側に1段分の空白を付けません。Home直後の左移動とEnd直後の右移動は止まります。これらの基準配置は、それまでの経路やズームに左右されません。リサイズ時も本文位置を復元します。

本文の重なりは `createLayout` に0を渡して固定します。過去に保存された重なり設定やCSS変数は参照せず、モード変更・リサイズ・ページ再読込後も0です。

表示枠の高さと位置は CSS の sticky で維持し、縦の切り抜きは共通のスクロール領域、段幅の切り抜きはスクロール面と一緒に動くレールの clip-path で行います。本文は共通のスクロール面を基準に配置するため、通常の縦横スクロールに JS の同期処理は使いません。速度・慣性・数式や表の中のスクロールはブラウザに任せます。wheel / touch ハンドラーは左右キーのアニメーションを中断するためだけに使い、上下端で横位置を補正しません。ネイティブの入力を打ち消す処理は使いません。ブラウザ上の平面は横128段（特に広い画面では表示幅+32段）・縦128画面分を上限とする有限な領域とし、端に近づくと原点とネイティブスクロール位置を同時に組み替えます。

画面外の先読み8段は設けず、横移動中に左右端で部分的に見える段までを覆う最小限の固定数のスロットを使い回します。全文DOMは元本文1個だけです。元本文を1段の表示と計測に使い、他の段には表示範囲に重なるブロックだけを複製します。`src/scripts/column-fragments.ts` が段落・見出し・リスト・表・折りたたみ・コード図版などの位置を計測し、二分探索で対象を絞ります。画像・フォント・折りたたみ・画面幅などによる再計測時以外は、元本文のレイアウトを読み直しません。各段は上下に最大160px（表示高さの1/4まで）の余裕を持ち、表示中の段では範囲内の断片を再利用し、離れたブロックは削除します。本文の範囲外で紙面が見えない枠は直前の断片を保持して更新せず、再び表示されるときに必要な内容へ更新します。親の `.post`、元の幅・座標、リスト先頭の折りたたまれた余白を保持して組版を合わせます。

元本文のIDとアクセシビリティツリーを保ち、表示断片だけを支援技術とTab移動から除外します。目次やキーボードで操作する対象を含む段には元本文を割り当て、フォーカス位置と表示位置を一致させます。折りたたみは元本文への対応番号を使い、先行する詳細が断片から省かれていても同じ項目を操作します。1段表示・印刷・ページ遷移時には元本文を通常の文書位置へ戻します。段の配置はレールの left と本文ルートの二軸 translate だけで更新し、座標を継承するCSS変数を本文ツリーに流しません。本文の横移動でも left を変更せず、段を再利用する際の本文全体の再レイアウトを避けます。形状と位置は前回適用した値を保持し、CSSOMによる値の文字列表現の違いで同じスタイルを再設定しません。変化していない位置情報はDOMに書き直さず、先頭・末尾で外向きの矢印キーを押しても同じ位置への再スクロールを行いません。ネイティブのスクロール位置はDOMを書き換える前に読み、本文断片を挿入する途中でレイアウトを読み直しません。これにより段を再利用するたびに残存する数式の全要素へスタイル再計算が波及することを避けます。

段の境界をまたいだときに本文の先頭と末尾に合わせてスクロール範囲を広げたり縮めたりします。全画面点の本文位置と横の端数を維持し、本文が残る端の部分段まで移動できます。末尾付近への目次・ハッシュ移動では、対象が画面右側の段に表示される場合があります。レールと平面で領域外を切り抜き、固定枠自体にはクリップを設定しません（スクロール時に後続の本文まで描画から落ちるため）。元本文を含む表示枠数の上限は「表示幅 / 段の周期を切り上げた数 + 1」で、記事の長さや移動距離に依存しません。先頭・末尾の端数段もこの上限に含めます。通常の横方向の入力は画面幅にかかわらず吸着せず自由にスクロールでき、左右キーでは全段を同時に1段分送れます。n段でも本文の縦横スクロールバーを表示し、本文の外周余白は段と一緒に流します。縦バー用の幅はブラウザーが確保し、ホイール・タッチ・キー操作も標準の動作を使います。スロット数が変わる場合も元本文と既存の枠を残し、必要な枠だけ追加・削除します。

- PageDown / Space: 見えている段数 × Sだけ縦に進む。
- PageUp / Shift+Space: 逆方向へ移動。
- 左右キー: 180msの減速アニメーションで1段分の横移動。連打時は移動先を合成し、逆方向の入力では現在位置から折り返します。ホイール・タッチ・ドラッグ・画面変更・ページ移動で中断します。動きを減らす設定ではアニメーションを省きます。Home / End: 先頭 / 末尾。
- 目次・数式参照・URL ハッシュ: 元本文の ID から位置を測り、到達できる候補のうち最短距離へ移動。

n段表示ではコードを段幅で折り返し、折り返した行は行番号（2桁分）の後ろにそろえます。横にスクロールする本文の中に、同じ向きにスクロールするコードを置かないためです。コピーされる内容は変わりません。数式と表は横スクロールのままです。1段表示のコードは折り返しません。

本文の操作要素は折りたたみとコードコピーです。折りたたみは元本文と全スロットで開閉状態を共有し、コードコピーは既存のイベント委譲で動作します。実行型コードやクライアント側の数式レンダラはありません。画像の実寸を計測するため、n段を有効にした記事では元本文の画像を先読みします。

制約: リスト・表・折りたたみなどはブロック全体を保持するため、単一の巨大なブロックではDOM削減幅が小さくなります。JSの更新が止まった状態で準備済みの断片を越えて移動すると、次の描画更新まで空白になる可能性があります。入力速度を制限して防ぐ処理は設けません。読書領域のスクロールバーは仮想平面内の操作用で、記事全体の進捗を表しません。原点の組み替えに応じてつまみの位置も変わります。先頭・末尾へはHome / Endで移動できます。横バーだけでも先頭・末尾の部分段まで到達でき、Home / Endで基準配置へ戻れます。ブラウザのページ内検索では表示断片もヒットする場合があります。別の段をまたぐ文字選択・コピーでは、各段が独立した本文断片であることが影響します。断片は支援技術と Tab 移動から除外し、元本文の ID とアクセシビリティツリーを残しています。現在のサイトはライトテーマで、n段表示も既存の本文色を使います。

`src/scripts/column-coordinates.ts` が1/1024 CSS px単位の整数で、唯一の論理座標・移動範囲・部分段の形を計算します。描画と境界判定は同じ座標を使い、描画時だけの吸着や微小量の引き算は使いません。`column-geometry.ts` は有限なブラウザー平面への投影、`column-viewport.ts` はネイティブの小数座標との変換だけを担当します。ブラウザーの観測値をまず同じ1/1024px単位へ変換し、その整数値同士の差分を入力として読みます。投影にも同じ整数化した観測値を使い、浮動小数の差分を後から丸めることで生じていた1単位の揺れを防ぎます。自分で書き込んだ値を論理座標として再解釈しないため、Home／Endの値や操作範囲が丸め誤差で変化しません。ズームによるスクロール領域と座標の丸めの違いはこの境界だけで正規化し、投影側で実際のオフセットを補償します。高さ0の段は幅も含めて完全に切り抜き、細い白い線を残しません。段の本文の translate は `column-geometry.ts` の `devicePixels` で 1/devicePixelRatio 単位に丸めます。段の周期がデバイスピクセルの整数倍にならない倍率（例: 125%で706 CSS px = 882.5デバイスピクセル）では、半端な位置に置いた段の文字を Chromium が再描画せずに動かし、ぼやけて見えたためです。`tests/column-pixel-grid.browser.test.mjs` は translate × devicePixelRatio が整数になることを確かめます（ヘッドレスの Chromium ではぼやけ自体は再現しません）。

整数座標・Home／Endの対称性・縦操作専用の余白・片軸操作・本文の被覆・有限平面・位置復元・ネイティブ座標の読み戻しの回帰テストは `npm test`、型チェックは `npm run astro -- check` で実行します。開発サーバでは長い記事、モバイル幅、斜めホイール、折りたたみ・コピー、ハッシュ、印刷、ClientRouter 遷移も確認してください。`tests/column-bounds.browser.test.mjs` は100%・110%・112.5%・125%・150%相当のズーム、重なり0固定・異なる縦位置で横操作だけで全文を読めることを確認します。縦操作で横位置が動かないこと、実際のホイール操作で端の部分段が高さ0まで縮み、上下端に追加余白が生じないこと、到達経路によらず同じ表示になることも検証します。横操作では外側余白を作れないこと、Home／Endの整数座標が毎回一致すること、縦操作で作った余白から横へ連続的に戻せることも確認します。

描画の回帰テストは、開発サーバまたはビルド済みサイトのプレビューを起動した状態で `npm run test:browser` を実行します。初回は `npx playwright-core install chromium` で検証用ブラウザを用意します。既存の Chromium は `TEST_BROWSER_PATH`、別のサーバは `TEST_BASE_URL` で指定できます。ChromiumとFirefoxの両方で実行するテストは、`TEST_ENGINES=chromium` のように実行するブラウザを絞れます。対象サイトのURL、ブラウザの起動、段組みの開始待ちなど、テストに共通の準備処理は `tests/browser.mjs` にまとめています。段組みが始まる前にスクロールすると失われるので、記事を操作するテストは `waitForColumnLayout` で待ってから操作します。テストはデスクトップ幅とモバイル幅で本文を縦横にスクロールし、段の下端まで正しい本文が描画されたことをスクリーンショットの画素で検証します。高速入力の移動量、表示枠と断片の再利用、表示外のブロックの削除、元本文と断片の組版・座標の一致を確認します。描画更新を停止してもネイティブには移動でき、更新再開後に表示枠を再利用することを確認します。実際の数式記事を12000px/秒・CPU速度1/4で往復し、残存する本文全体へのスタイル再計算が再発していないことも検証します。

`tests/column-review-fixes.browser.test.mjs` は本文内リンク・ハッシュ・再読み込み・モード切り替え時の読書位置と、目次・折りたたみのキーボードフォーカスを確認します。`tests/column-edges.browser.test.mjs` は切り替えボタンが直接表示されること、実際のネイティブ横バーのドラッグ、Home / Endで先頭・末尾の基準配置へ到達できることを検証します。`tests/column-margins.browser.test.mjs` は本文の余白が横移動と一緒に画面外へ流れ、横バーの左右余白が固定されることを確認します。

`tests/column-motion.browser.test.mjs` は左右キーのアニメーション・連打・中断・動きを減らす設定、ヘッダー下端の3pxバー、固定した横バーと流れる本文の余白を確認します。

`tests/column-scroll-performance.browser.test.mjs` は100%・110%・112.5%・125%・150%相当の拡大表示で、段内の横移動が実際に進みながら本文・背景・レールのスタイルと本文DOMを更新しないことを確認します。小数のネイティブ座標で往復しても投影原点が揺れず、誤差が蓄積しないことはユニットテストで確認します。

一覧はヘッダーの下にある領域自身をスクロールし、記事と共通の太さ・色・矢印を持つ標準バーを使います。スクロール位置は一覧領域から保存・復元します。`ArticleIndex.astro` を共通レイアウトに置き、`transition:persist` で記事への遷移・一覧への復帰・記事間移動でも同じDOMを保持します。1段・n段とも、開く直前の一覧位置で背景を固定し、透かしとぼかしを重ねます。背景の一覧は `inert` と `aria-hidden` で操作対象から外し、閉じたときは一覧位置と該当カードへのフォーカスを復元します。遷移先HTMLの取得は通常のClientRouterに任せます。

紙面の色・影・丸角は `--note-surface`・`--note-shadow`・`--note-radius` で共通化しています。n段は実際の本文先頭の上2隅、末尾の下2隅だけを丸め、続く端は直角にします。段間や紙面外クリックで一覧へ戻り、選択解除・ドラッグ・ネイティブバー操作では閉じません。上部目次の左右には高さ12pxの正三角形のボタンを置き、見出し行の中央にそろえます。操作領域は32×36pxで、クリック・長押し・キーボードで目次だけを動かします。下端のスクロールバーは3pxのままです。`tests/column-background.browser.test.mjs` は背景DOM・位置・履歴移動・フォーカスの保持、角の形、誤遷移防止、印刷、目次矢印を確認します。

## 記事を開くまでの処理

一覧から記事を開くとき（ClientRouter による遷移）と、記事を直接読み込むときの表示を速くするため、次の処理を入れています。経緯と計測値は `docs/column-preload-investigation.md` にあります。

- 数式フォントの先読み（`src/scripts/math-font-prefetch.ts`、`lib/math-fonts.ts`）: ビルド時に記事ごとの数式フォントを `data-math-fonts` に書き出し、一覧のカードに80msホバーまたはフォーカスすると `FontFace.load()` で読み込みます。タッチ、オフライン、データ節約、2G回線では行いません。`astro:before-swap` で読み込み済みのフォントを `document.fonts` に記事の `@font-face` と同じ名前で加え、遷移先の文書から同じフォントの `@font-face` と preload を取り除きます。
- 数式フォントの preload（`src/pages/[slug].astro`）: 記事が使う数式フォントをすべて `<link rel="preload">` で読み込みます。最初のレイアウトの途中で見つかったフォントはそのレイアウトの後に届き、届くたびに記事全体をレイアウトし直すためです。Nunito は preload しません。FCP が遅れるだけで、レイアウトの回数は減らなかったためです。
- n段で本文を段へ入れている間（`cl-premount`）は、目次が見出しの位置を読みません（`src/components/Toc.astro`）。n段では `column-layout.ts` が `cl:heading` で現在の見出しを伝えるので、ここで位置を読むと、記事全体のレイアウトを強制するだけになります。1段で始めるときは、段組みが `cl:single` を送り、目次がそこで位置を合わせます。
- n段の本文を先に段へ入れる（`src/layouts/Layout.astro` の head のスクリプト）: 遷移先URLの `?columns=`、指定がなければ保存された選択でn段になるときだけ、遷移では `astro:before-swap`、直接の読み込みでは MutationObserver で `.cl-source` を段の幅の枠へ移し、本文を1段の幅でレイアウトしないようにします。本文の途中にインラインスクリプトは置きません。
- 準備中の本文は `clip-path: inset(50%)` と、スクロールポートの `aria-hidden="true"` で隠します。`visibility: hidden` は外すときに本文全体のスタイル計算を起こすので使いません。JavaScript が無いときは何も付けません。準備中は Tab キーを無視し、隠れた本文にフォーカスが入らないようにします。`inert` は `visibility` と同じく付け外しで本文全体のスタイル計算を起こすので使いません。
- `astro.config.mjs` の Vite プラグインが、Tailwind Typography の `[class~=not-prose]` を `.not-prose` に書き換えます。`<html>` のクラスが変わるたびに Chromium が文書全体のスタイルを計算し直すのを避けるためです。

計測は本番ビルドを `astro preview` で配信して行います。

```sh
npm run build && npx astro preview
TRACE=0 node scripts/measure-article-open.mjs http://localhost:4321/dispositif/ 3 > out.jsonl
```

`ENGINES`・`ARTICLES`・`MODES`・`CACHES` で条件を絞り、`NAV=direct` で直接の読み込みを測ります。トレースは時間を延ばすので、壁時計の比較は `TRACE=0` で行います。計測中に他の重い処理があると回ごとに±30ms程度揺れるので、小さな差は12回以上交互に測って確かめます。
