# [Dispositif](https://elle-et-noire.github.io/dispositif/)

Astroベースの記事サイトです。記事はビルド時にMarkdownからHTMLへ変換し、数式はMathJax v4のCHTMLとして出力します。ブラウザ側ではMathJaxを実行せず、数式フォントも同一オリジンから配信します。

## 構成

```text
/
├── lib/                    # 記事取得、Markdown前処理、MathJax変換
├── post/                   # Markdown記事
├── public/
│   └── fonts/mjx/          # predev / prebuildで生成
├── scripts/
│   └── copy-math-fonts.mjs
└── src/
    ├── components/
    ├── layouts/
    ├── pages/
    │   ├── index.astro
    │   └── [slug].astro
    └── styles/globals.css
```

## コマンド

```sh
npm install
npx astro dev --background
npm run build
npm run astro -- check
```

バックグラウンドの開発サーバーは次のコマンドで管理できます。

```sh
npx astro dev status
npx astro dev logs
npx astro dev stop
```

## 記事の読書モード

記事右上の「1段 / n段」で切り替えます。選択は `localStorage` に保存し、未選択時は画面幅が段の周期の2倍以上なら n段にします。JavaScript 無効時と印刷時は通常のレイアウトです。

1段表示では見出しを縦に並べた目次を本文右側に常時表示し、本文のスクロールに追従します。画面幅768px未満では上部の「目次」で同じ縦並びリストを開閉します。n段表示では上部の「目次」を押すと、各見出しを縦書きにして横に並べた一覧が開きます。縦書きでは高さの上限（`--toc-heading-height: min(12rem, 35dvh)`）で隣の行へ折り返し、横スクロールバー・タッチ操作・マウスホイールで移動できます。どちらの目次も読書中の見出しを強調して表示範囲に収めます。折りたたみ目次は見出しの選択・外側のクリック・Escで閉じます。上部の目次は本文に重ねて開くため、開閉で本文の配置やn段の読書位置は変わりません。JavaScript無効時も1段表示の目次とリンクを利用できます。記事一覧へは右上の閉じるボタン（1段の広い画面ではヘッダの「記事一覧」も）で戻ります。

段幅と間隔は `src/styles/reading-mode.css` の CSS 変数で調整できます。

```css
:root {
  --rm-column-width: min(38em, calc(100vw - 2rem));
  --rm-gap: 2rem;
  --rm-column-padding: clamp(1rem, 2vw, 1.5rem);
  --rm-reader-space: clamp(0.5rem, 1.25dvh, 0.75rem);
  --rm-context-overlap: 0.75lh;
  --rm-surface: #f8f8f8;
  --rm-ink: #324e73;
}
```

`ReadingMode.astro` と `src/scripts/reading-mode.ts` が全記事を拡張します。各段の表示枠はヘッダ・操作バーと上下の余白を除いた読書領域と同じ高さで固定します。縦にスクロールすると枠はその場に残り、全段の本文が一斉に上へ流れます。左段の下端と右段の上端には既定で3/4行分の同じ本文を重ね、重複部分だけを穏やかに薄く表示します。上下端に同じ字形が残ることで本文のつながりを追えるようにしています。

段の左右には16〜24px、記事冒頭には同じ量の余白を設けます。段幅は余白を含む幅で、元本文と複製に同じ余白を適用して組版・計測を一致させます。読書領域の上下には8〜12pxの余裕を取り、その内側の高さをHとします。各段の上下端で本文を隠す余白は追加せず、段の連続性を維持します。これらの余白はn段モードだけに適用します。

段は左右へ仮想的に続き、初期表示の段番号を0、左隣を−1、−2…とします。高さを H、重なりを o、段の周期を P とすると、本文の進みは S = H − o、段 k の表示位置は t = k × S + y です。初期状態は段0が左端です。Sだけ縦に読み進めるごとに左側を1段ずつ開放し、Sだけ下へ進んで1段左へ移ると同じ本文位置に戻ります。左端は k = −floor(y / S)、上端は y = −k × S としてネイティブスクロールの領域そのものを調整し、本文の先頭より前には進めないようにします。右端も本文の末尾に届く段で止め、空の段や重なり部分だけの段を増やしません。最後の段の途中で本文が終わる場合、その余白は残します。画面より短い記事は1段だけ表示します。

n段モードでは右上の「重なり」入力で本文の重複量を1px刻みで変更できます。読書位置を保ってすぐ反映し、値は `localStorage` に保存します。`0px` で重複をなくせます。上限は表示高さの1/4で、リサイズ時は入力値も実際に適用している範囲に合わせます。未設定時の既定値は `--rm-context-overlap` で指定し、px単位に丸めて使用します。

表示枠の高さと位置は CSS の sticky で維持し、縦の切り抜きは共通のスクロール領域、段幅の切り抜きはスクロール面と一緒に動くレールの clip-path で行います。本文は共通のスクロール面を基準に配置するため、通常の縦横スクロールに JS の同期処理は使いません。読書領域に wheel ハンドラーは置かず、速度・慣性・数式やコード内のスクロールはブラウザに任せます。ブラウザ上の平面は横128段（特に広い画面では表示幅+32段）・縦128画面分を上限とする有限な領域とし、端に近づくと原点とネイティブスクロール位置を同時に組み替えます。

スロットの先読みは通常左右4段分、速い移動では120ms先の位置を目安に進行方向へ最大2段分を振り替えます。逆側にも少なくとも2段分を残し、急な反転に備えます。速度が上がっても本文複製を増やしません。段の配置は該当する枠と本文ルートの left / translate のみ更新し、座標を継承するCSS変数を本文ツリーに流しません。これにより段を再利用するたびに数式の全要素へスタイル再計算が波及することを避けます。

段の境界をまたいだときに本文の先頭と末尾に合わせてスクロール範囲を広げたり縮めたりします。通常は全画面点の本文位置と横の端数を維持し、末尾を越える操作は最後の段までに制限します。末尾付近への目次・ハッシュ移動では、対象が画面右側の段に表示される場合があります。レールと平面で領域外を切り抜き、固定枠自体にはクリップを設定しません（スクロール時に後続の本文まで描画から落ちるため）。複製数の上限は「表示幅 / 段の周期を切り上げた数 + 9」で、記事の長さや移動距離に依存しません。横方向は画面幅にかかわらず吸着せず自由にスクロールできます。部分的に見える段を含めた画面内の段と、前後の余裕を確保する定数個のスロットを使い回します。複製数が変わる場合も表示中の枠を残し、必要な枠だけ追加・削除します。

- PageDown / Space: 見えている段数 × Sだけ縦に進む。
- PageUp / Shift+Space: 逆方向へ移動。
- 左右キー: 1段分の横移動。Home / End: 先頭 / 末尾。
- 目次・数式参照・URL ハッシュ: 元本文の ID から位置を測り、到達できる候補のうち最短距離へ移動。

本文の操作要素は折りたたみとコードコピーです。折りたたみは元本文と全スロットで開閉状態を共有し、コードコピーは既存のイベント委譲で動作します。実行型コードやクライアント側の数式レンダラはありません。画像の実寸を計測するため、n段を有効にした記事では元本文の画像を先読みします。

制約: JSの長時間停止中に先読み範囲を越える極端な移動を行うと、次の描画更新まで空白になる可能性があります。入力速度を制限して防ぐ処理は設けません。読書領域のスクロールバーは仮想平面内の操作用で、記事全体の進捗を表しません。原点の組み替えに応じてつまみの位置も変わります。先頭・末尾へはHome / Endを使えます。ブラウザのページ内検索では複製もヒットする場合があります。別の段をまたぐ文字選択・コピーでは、各段が独立した本文複製であることが影響します。複製は支援技術と Tab 移動から除外し、元本文の ID とアクセシビリティツリーを残しています。現在のサイトはライトテーマで、読書モードも既存の本文色を使います。

座標・最短移動・スロット数・位置復元の回帰テストは `npm test`、型チェックは `npm run astro -- check` で実行します。開発サーバでは長い記事、モバイル幅、斜めホイール、折りたたみ・コピー、ハッシュ、印刷、ClientRouter 遷移も確認してください。

描画の回帰テストは、開発サーバを起動した状態で `npm run test:browser` を実行します。初回は `npx playwright-core install chromium` で検証用ブラウザを用意します。既存の Chromium は `RM_BROWSER_PATH`、別のサーバは `RM_BASE_URL` で指定できます。テストはデスクトップ幅とモバイル幅で本文を縦横にスクロールし、段の下端まで正しい本文が描画されたことをスクリーンショットの画素で検証します。高速入力の移動量、先読み範囲内で更新前の全可視段、枠を増減した際の再利用を確認します。描画更新を停止しても先読み範囲内ではネイティブに移動でき、本文が描かれることを画素で検証します。実際の数式記事を12000px/秒・CPU速度1/4で往復し、本文全体へのスタイル再計算が再発していないことも検証します。
