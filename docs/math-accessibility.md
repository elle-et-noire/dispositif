# 数式の読み上げ方式の決定記録

ROADMAP 2.3（数式のアクセシビリティ）で、数式を支援技術にどう読ませるかを決めた記録。残っている確認作業は `ROADMAP.md` の 2.3 にある。

## 変更前の状態

CHTMLの字形の箱（`mjx-c`）には 𝑎 や + などの文字が入っている。Chromiumのアクセシビリティツリーでは、これらの文字が構造なしに並んでいた（x^2 が「x2」になる）。

## 決定（2026-11-08、PR #14）

- 各数式の `mjx-container` に `role="img"` と、TeXのソースを `aria-label` として付ける（`lib/mathjax.ts`、`lib/math-speech.ts`）。前処理で足す前後の `\hspace` と、`\label`・`\tag` は除き、見えている式番号を末尾に「(1)」のように足す。字形の箱 `mjx-math` には `aria-hidden` を付け、二重に読まれないようにする（`tests/math-speech.browser.test.mjs`）。
- `\eqref` を含む数式は中にリンクがある。`img` にするとリンクが支援技術から消えるのにTabでは止まるので、手を加えない。
- HTMLは数式記事で約3.5%増える。記事を開くまでの時間は計測の誤差の範囲だった。

## 採らなかった案

### MathJaxの見えないMathML（`a11y/assistive-mml`）

ビルド時に使えるが、隠すためのCSSは自分で足す必要がある。

- 数式記事で要素数が9260から13566に増え、記事を開くまでがChromiumで +56〜146 ms、Firefoxで +71〜246 ms 遅くなった。
- MathMLに `content-visibility: auto` を付けるとChromiumは戻ったが、画面外の数式がアクセシビリティツリーから消えた（196個 → 1個）。
- MathMLを数式として読み上げるMathCATなどは日本語に対応していない。
- 費用の内訳（数式記事の本文を文書へ入れて7回測った中央値の差）は、パース +4〜5 ms、スタイル計算 +12〜18 ms、レイアウトがChromium +38 ms・Firefox +79 ms（文書で1回目は +168 ms）で、大半はレイアウトだった。MathMLの中を `display: inline` にしても、Firefoxのレイアウトは +70 ms までしか減らなかった。

### MathMLを表示後に差し込む方式

MathMLを `<template>` に入れておき、表示後に手の空いた時間で8式ずつ差し込む。

- 記事を開くまでの時間はChromiumで変わらず、Firefoxで一覧からの遷移が +2〜+49 ms だった。
- 表示後、Chromiumで合計75〜135 ms（1回最長約10 ms）、Firefoxで合計265〜340 ms（1回最長20〜33 ms）の処理が0.5〜3.6秒続き、差し込むまでは数式を読めない。
- 本文に約4300要素が残るので、幅の変更や1段・n段の切り替えで本文を組み直すたびに、Firefoxで約80 msが加わる。
- 日本語の読み上げでMathMLの利点が生きるか分からないので採らなかった。

上の2案の試作はローカルのブランチ `a11y/assistive-mml` にある。

### その他

- 読み上げ文字列を作るSREは日本語の規則がないので使わない。
- `role="math"` は、NVDAがMathMLのない要素を読まなかった報告があるので使わない。
