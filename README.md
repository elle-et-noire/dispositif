# [Dispositif](https://elle-et-noire.github.io/dispositif/)

Astroベースの記事サイトです。記事はビルド時にMarkdownからHTMLへ変換し、数式はMathJax v4のCHTMLとして出力します。ブラウザ側ではMathJaxを実行せず、数式フォントも同一オリジンから配信します。

## 構成

```text
/
├── lib/                    # 記事取得、Markdown前処理、MathJax変換
├── post/                   # Markdown記事
├── public/
│   └── fonts/mjx/          # predev / prebuildで生成
├── scripts/
│   └── copy-math-fonts.mjs
└── src/
    ├── components/
    ├── layouts/
    ├── pages/
    │   ├── index.astro
    │   └── [slug].astro
    └── styles/globals.css
```

## コマンド

```sh
npm install
npm run dev -- --background
npm run build
npm run astro -- check
```

バックグラウンドの開発サーバーは次のコマンドで管理できます。

```sh
npx astro dev status
npx astro dev logs
npx astro dev stop
```

数式フォントは `predev` / `prebuild` の `scripts/copy-math-fonts.mjs` で用意します。起動中の開発サーバーの配信を維持するため、フォントディレクトリは削除せず、変更のないファイルも書き直しません。`tests/math-fonts.browser.test.mjs` は、準備処理の再実行後も全フォントを配信でき、1段・n段・記事遷移後にも数式フォントを読み込めることを確認します。

## 記事の読書モード

1段では記事右上の「1段 / n段」で直接切り替えます。記事の配置・余白・目次はmainの通常表示に合わせ、閉じるボタンとモバイル目次の既存の操作行に段切り替えを置きます。n段では目次の右端の「表示設定」を開いて切り替えます。設定パネルは本文に重ねて開き、外側のクリック・Escで閉じます。選択は `localStorage` に保存し、未選択時は画面幅が段の周期の2倍以上なら n段にします。JavaScript 無効時と印刷時は通常のレイアウトです。

1段表示では見出しを縦に並べた目次を本文右側に常時表示し、本文のスクロールに追従します。画面幅768px未満では記事右上の矢印で同じ縦並びリストを開閉します。n段表示では見出しを横書きで上部に横一列へ並べ、折りたたまず常時表示します。収まらない分は横スクロールバー・タッチ操作・マウスホイールで移動でき、長い見出しも省略せず一行で表示します。見出しの選択・外側のクリック・Escでもn段の目次は開いたままです。どちらの目次も読書中の見出しを強調して表示範囲に収めます。上部の目次は3pxの細いスクロールバーをヘッダー下端に余白なしで配置し、ホバー・フォーカス時に少し濃くします。標準の太さ指定しか使えないブラウザーではthinを使います。目次と設定は高さ3.5remのヘッダに収まり、目次内の移動で本文の配置や読書位置は変わりません。1段表示の折りたたみ目次は見出しの選択・外側のクリック・Escで閉じます。JavaScript無効時も1段表示の目次とリンクを利用できます。記事一覧へは右上の閉じるボタン（1段の広い画面ではヘッダの「記事一覧」も）で戻ります。

段幅と間隔は `src/styles/reading-mode.css` の CSS 変数で調整できます。

```css
:root {
  --rm-column-width: min(38em, calc(100vw - 2rem));
  --rm-gap: 1rem;
  --rm-edge-space: 1rem;
  --rm-column-padding: clamp(1rem, 2vw, 1.5rem);
  --rm-reader-space: 1rem;
  --rm-context-overlap: 0.75lh;
  --rm-surface: #f8f8f8;
  --rm-ink: #324e73;
}
```

`ReadingMode.astro` と `src/scripts/reading-mode.ts` が全記事を拡張します。各段の表示枠はヘッダと上下の余白を除いた読書領域と同じ高さで固定します。縦にスクロールすると枠はその場に残り、全段の本文が一斉に上へ流れます。左段の下端と右段の上端には既定で3/4行分の同じ本文を重ね、重複部分だけを穏やかに薄く表示します。上下端に同じ字形が残ることで本文のつながりを追えるようにしています。

段の左右には16〜24px、記事冒頭には同じ量の余白を設けます。段幅は余白を含む幅で、元本文と複製に同じ余白を適用して組版・計測を一致させます。本文の外周余白は `--rm-edge-space`（既定1rem）で指定し、スクロール面の先頭と末尾に置きます。横移動に合わせて余白も画面外へ流れ、本文は画面端まで表示できます。横スクロールバーだけは左右に固定した同じ幅の余白を残します。トラック余白を指定できない環境では、本文と横位置を同期するネイティブバーを別枠で配置します。狭い画面でも両端の余白を含めて1段が収まるよう段幅を調整します。段間・ヘッダー直下・外周の余白はすべて既定16pxにそろえ、その内側の表示高さをHとします。各段の上下端で本文を隠す余白は追加せず、段の連続性を維持します。これらの余白はn段モードだけに適用します。

段は左右へ仮想的に続き、初期表示の段番号を0、左隣を−1、−2…とします。高さを H、重なりを o、段の周期を P とすると、本文の進みは S = H − o、段 k の表示位置は t = k × S + y です。初期状態は段0が左端です。Sだけ縦に読み進めて1段左へ移ると同じ本文位置に戻ります。

本文の先頭・末尾では部分段を許します。端に近づくにつれて、隣の段にも含まれる重複部分だけを連続的に縮めます。全文を含む段は変えず、重なりだけになった端の段は高さ0にします。末尾の部分段は上端、先頭の部分段は下端を他の段にそろえ、削った重複分だけ残る本文も一緒に移動します。白い面・重なりの帯・文字の切り抜きを同じ範囲にそろえ、消えた場所は背景になります。新しい本文を隠さないよう、削る範囲を隣の段との重複内に制限します。背景面は本文とは別の要素にし、座標変更が数式全体のスタイル再計算へ波及しないようにしています。途中の段では指定された重なりを維持しますが、端の部分段では実際の重複表示を徐々に減らします。画面より短い記事は、本文の高さの1段だけを上揃えで表示します。

通常の横操作では、実際に本文が残る先頭段が左端、末尾段が右端にそろう位置まで移動できます。外側に空白を作るためだけの横移動はできません。縦操作では、横位置を固定したまま端の部分段が完全に消える位置まで進め、最大1段分の外側余白を作れます。その状態から横へ戻すと、縦位置を保ったまま連続的に内側へ移動でき、余白を増やす方向へは動けません。途中で縦位置が変わっても、横位置を通常範囲へ自動で戻しません。この制限は現在の座標から決め、到達経路を示すフラグは持ちません。狭い画面でも部分段を横から読め、縦位置を固定した横操作だけで本文全体を読めます。記事全体が画面幅より短い場合は先頭側にそろえ、1画面の高さ以下の記事は1段に固定します。縦操作では横位置を、横操作では縦位置を変えません。上下端での自動横誘導は行わず、上下の停止位置にも重なり分の追加余白を設けません。記事の先頭・末尾が基準段の上端・下端にそろう位置で止め、隣の重複だけの部分段はその時点で消えます。

端の部分段では、スクロール面と一緒に動くレールの切り抜きを白い面に合わせます。固定枠そのものには切り抜きを設定せず、本文の組版を保持します。原点変更の補助座標はCSS変数ではなくdata属性に記録し、数式ツリーへの不要なスタイル再計算を避けます。

同じ論理座標なら、到達経路によらず本文と白い面は同じ配置になります。縦操作が止まった画面を常に同じ配置へ吸着させる処理はありません。Home／「先頭へ」は先頭段を左端、End／「末尾へ」は末尾段を右端にそろえ、外側に1段分の空白を付けません。Home直後の左移動とEnd直後の右移動は止まります。これらの基準配置は、それまでの経路やズームに左右されません。リサイズ・重なり変更時も本文位置を復元します。

n段モードでは「表示設定」内の「重なり」入力で本文の重複量を1px刻みで変更できます。読書位置を保ってすぐ反映し、値は `localStorage` に保存します。`0px` で重複をなくせます。上限は表示高さの1/4で、リサイズ時は入力値も実際に適用している範囲に合わせます。未設定時の既定値は `--rm-context-overlap` で指定し、px単位に丸めて使用します。

表示枠の高さと位置は CSS の sticky で維持し、縦の切り抜きは共通のスクロール領域、段幅の切り抜きはスクロール面と一緒に動くレールの clip-path で行います。本文は共通のスクロール面を基準に配置するため、通常の縦横スクロールに JS の同期処理は使いません。速度・慣性・数式やコード内のスクロールはブラウザに任せます。wheel / touch ハンドラーは左右キーのアニメーションを中断するためだけに使い、上下端で横位置を補正しません。ネイティブの入力を打ち消す処理は使いません。ブラウザ上の平面は横128段（特に広い画面では表示幅+32段）・縦128画面分を上限とする有限な領域とし、端に近づくと原点とネイティブスクロール位置を同時に組み替えます。

画面外の先読み8段は設けず、横移動中に左右端で部分的に見える段までを覆う最小限の固定数のスロットを使い回します。全文DOMは元本文1個だけです。元本文を1段の表示と計測に使い、他の段には表示範囲に重なるブロックだけを複製します。`src/scripts/reading-fragments.ts` が段落・見出し・リスト・表・折りたたみ・コード図版などの位置を計測し、二分探索で対象を絞ります。画像・フォント・折りたたみ・画面幅などによる再計測時以外は、元本文のレイアウトを読み直しません。各段は上下に最大160px（表示高さの1/4まで）の余裕を持ち、範囲内の移動では断片を再利用し、離れたブロックは削除します。親の `.post`、元の幅・座標、リスト先頭の折りたたまれた余白を保持して組版を合わせます。

元本文のIDとアクセシビリティツリーを保ち、表示断片だけを支援技術とTab移動から除外します。折りたたみは元本文への対応番号を使い、先行する詳細が断片から省かれていても同じ項目を操作します。1段表示・印刷・ページ遷移時には元本文を通常の文書位置へ戻します。段の配置はレールの left と本文ルートの二軸 translate だけで更新し、座標を継承するCSS変数を本文ツリーに流しません。本文の横移動でも left を変更せず、段を再利用する際の本文全体の再レイアウトを避けます。形状と位置は前回適用した値を保持し、CSSOMによる値の文字列表現の違いで同じスタイルを再設定しません。ネイティブのスクロール位置はDOMを書き換える前に読み、本文断片を挿入する途中でレイアウトを読み直しません。これにより段を再利用するたびに残存する数式の全要素へスタイル再計算が波及することを避けます。

段の境界をまたいだときに本文の先頭と末尾に合わせてスクロール範囲を広げたり縮めたりします。全画面点の本文位置と横の端数を維持し、本文が残る端の部分段まで移動できます。末尾付近への目次・ハッシュ移動では、対象が画面右側の段に表示される場合があります。レールと平面で領域外を切り抜き、固定枠自体にはクリップを設定しません（スクロール時に後続の本文まで描画から落ちるため）。元本文を含む表示枠数の上限は「表示幅 / 段の周期を切り上げた数 + 1」で、記事の長さや移動距離に依存しません。先頭・末尾の端数段もこの上限に含めます。通常の横方向の入力は画面幅にかかわらず吸着せず自由にスクロールでき、左右キーでは全段を同時に1段分送れます。n段では本文の縦スクロールバーを隠し、本文の外周余白は段と一緒に流します。横スクロールバーと縦のホイール・タッチ・キー操作は残します。スロット数が変わる場合も元本文と既存の枠を残し、必要な枠だけ追加・削除します。

- PageDown / Space: 見えている段数 × Sだけ縦に進む。
- PageUp / Shift+Space: 逆方向へ移動。
- 左右キー: 180msの減速アニメーションで1段分の横移動。連打時は移動先を合成し、逆方向の入力では現在位置から折り返します。ホイール・タッチ・ドラッグ・画面変更・ページ移動で中断します。動きを減らす設定ではアニメーションを省きます。Home / End: 先頭 / 末尾。
- 目次・数式参照・URL ハッシュ: 元本文の ID から位置を測り、到達できる候補のうち最短距離へ移動。

本文の操作要素は折りたたみとコードコピーです。折りたたみは元本文と全スロットで開閉状態を共有し、コードコピーは既存のイベント委譲で動作します。実行型コードやクライアント側の数式レンダラはありません。画像の実寸を計測するため、n段を有効にした記事では元本文の画像を先読みします。

制約: リスト・表・折りたたみなどはブロック全体を保持するため、単一の巨大なブロックではDOM削減幅が小さくなります。JSの更新が止まった状態で準備済みの断片を越えて移動すると、次の描画更新まで空白になる可能性があります。入力速度を制限して防ぐ処理は設けません。読書領域のスクロールバーは仮想平面内の操作用で、記事全体の進捗を表しません。原点の組み替えに応じてつまみの位置も変わります。先頭・末尾へはHome / End、または「表示設定」の「先頭へ／末尾へ」を使えます。横バーだけでも先頭・末尾の部分段まで到達でき、これらのボタンでは基準配置へ戻れます。ブラウザのページ内検索では表示断片もヒットする場合があります。別の段をまたぐ文字選択・コピーでは、各段が独立した本文断片であることが影響します。断片は支援技術と Tab 移動から除外し、元本文の ID とアクセシビリティツリーを残しています。現在のサイトはライトテーマで、読書モードも既存の本文色を使います。

`src/scripts/reading-coordinates.ts` が1/1024 CSS px単位の整数で、唯一の論理座標・移動範囲・部分段の形を計算します。描画と境界判定は同じ座標を使い、描画時だけの吸着や微小量の引き算は使いません。`reading-geometry.ts` は有限なブラウザー平面への投影、`reading-viewport.ts` はネイティブの小数座標との変換だけを担当します。ブラウザーの観測値をまず同じ1/1024px単位へ変換し、その整数値同士の差分を入力として読みます。投影にも同じ整数化した観測値を使い、浮動小数の差分を後から丸めることで生じていた1単位の揺れを防ぎます。自分で書き込んだ値を論理座標として再解釈しないため、Home／Endの値や操作範囲が丸め誤差で変化しません。ズームによるスクロール領域と座標の丸めの違いはこの境界だけで正規化し、投影側で実際のオフセットを補償します。高さ0の段は幅も含めて完全に切り抜き、細い白い線を残しません。

整数座標・Home／Endの対称性・縦操作専用の余白・片軸操作・本文の被覆・有限平面・位置復元・ネイティブ座標の読み戻しの回帰テストは `npm test`、型チェックは `npm run astro -- check` で実行します。開発サーバでは長い記事、モバイル幅、斜めホイール、折りたたみ・コピー、ハッシュ、印刷、ClientRouter 遷移も確認してください。`tests/reading-bounds.browser.test.mjs` は100%・110%・112.5%・125%・150%相当のズーム、重なり0px・21px、異なる縦位置で横操作だけで全文を読めることを確認します。縦操作で横位置が動かないこと、実際のホイール操作で重複だけの白い面が高さ0まで縮み、上下端に追加余白が生じないこと、到達経路によらず同じ表示になることも検証します。横操作では外側余白を作れないこと、Home／Endの整数座標が毎回一致すること、縦操作で作った余白から横へ連続的に戻せることも確認します。

描画の回帰テストは、開発サーバまたはビルド済みサイトのプレビューを起動した状態で `npm run test:browser` を実行します。初回は `npx playwright-core install chromium` で検証用ブラウザを用意します。既存の Chromium は `RM_BROWSER_PATH`、別のサーバは `RM_BASE_URL` で指定できます。テストはデスクトップ幅とモバイル幅で本文を縦横にスクロールし、段の下端まで正しい本文が描画されたことをスクリーンショットの画素で検証します。高速入力の移動量、表示枠と断片の再利用、表示外のブロックの削除、元本文と断片の組版・座標の一致を確認します。描画更新を停止してもネイティブには移動でき、更新再開後に表示枠を再利用することを確認します。実際の数式記事を12000px/秒・CPU速度1/4で往復し、残存する本文全体へのスタイル再計算が再発していないことも検証します。

`tests/reading-edges.browser.test.mjs` は設定が本文の高さを変えないこと、実際のネイティブ横バーのドラッグ、マウスだけで先頭・末尾の基準配置へ到達できることを検証します。`tests/reading-margins.browser.test.mjs` は本文の余白が横移動と一緒に画面外へ流れ、横バーの左右余白が固定されることを確認します。

`tests/reading-motion.browser.test.mjs` は左右キーのアニメーション・連打・中断・動きを減らす設定、ヘッダー下端の3pxバー、固定した横バーと流れる本文の余白を確認します。

`tests/reading-scroll-performance.browser.test.mjs` は100%・110%・112.5%・125%・150%相当の拡大表示で、段内の横移動が実際に進みながら本文・背景・レールのスタイルと本文DOMを更新しないことを確認します。小数のネイティブ座標で往復しても投影原点が揺れず、誤差が蓄積しないことはユニットテストで確認します。

一覧は `ArticleIndex.astro` を共通レイアウトに置き、`transition:persist` で記事への遷移・一覧への復帰・記事間移動でも同じDOMを保持します。1段・n段とも、開く直前の一覧位置で背景を固定し、透かしとぼかしを重ねます。背景の一覧は `inert` と `aria-hidden` で操作対象から外し、閉じたときは一覧位置と該当カードへのフォーカスを復元します。遷移先HTMLの取得は通常のClientRouterに任せます。
