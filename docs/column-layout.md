# 段組みの実装

記事の1段・n段の表示をどう組み立てているかを説明します。閲覧者から見た動作は `README.md` の「記事の段組み」、各テストが確かめることは `README.md` の「テスト」にあります。

## 構成と余白

`ColumnLayout.astro` と `src/scripts/column-layout.ts` が全記事を拡張します。各段の表示枠はヘッダと上下の余白を除いた読書領域と同じ高さで固定します。縦にスクロールすると枠はその場に残り、全段の本文が一斉に上へ流れます。

段の左右と記事冒頭には同じ量の余白（`--cl-column-padding`）を設けます。段幅は余白を含む幅で、元本文と複製に同じ余白を適用して組版・計測を一致させます。本文の外周余白は `--cl-edge-space` で指定し、スクロール面の先頭と末尾に置きます。横移動に合わせて余白も画面外へ流れ、本文は画面端まで表示できます。縦横とも本文自身の標準スクロールバーを使います。1段表示では、画面全体を覆う透明な記事用スクロール領域自身の標準バーを同じ太さ・色・矢印で表示します。背景の一覧・ヘッダー・透かしはその領域の外に置き、バーの透明なトラック越しにも背景がそのまま見える構造にします。記事ページの文書自体はスクロールさせません。印刷時は通常の文書フローに戻します。バーの太さは `--cl-scrollbar-size` で指定し、太さを指定できないブラウザーではthinを使います。狭い画面でも両端の余白を含めて1段が収まるよう段幅を調整します。段間・ヘッダー直下・外周の余白は同じ値にそろえ、その内側の表示高さをHとします。各段の上下端で本文を隠す余白は追加せず、段の連続性を維持します。これらの余白はn段だけに適用します。

## 座標と移動範囲

段は左右へ仮想的に続き、初期表示の段番号を0、左隣を−1、−2…とします。高さをH、段の横の周期をPとすると、段kの表示位置は t = k × H + y です。初期状態は段0が左端です。Hだけ縦に読み進めて1段左へ移ると同じ本文位置に戻ります。

本文の先頭・末尾では部分段を許します。末尾の部分段は上端、先頭の部分段は下端を他の段にそろえ、本文がない部分では白い面と文字を同じ範囲で切り抜きます。背景面は本文とは別の要素にし、座標変更が数式全体のスタイル再計算へ波及しないようにしています。画面より短い記事は、本文の高さの1段だけを上揃えで表示します。

通常の横操作では、実際に本文が残る先頭段が左端、末尾段が右端にそろう位置まで移動できます。外側に空白を作るためだけの横移動はできません。縦操作では、横位置を固定したまま端の部分段が完全に消える位置まで進め、最大1段分の外側余白を作れます。その状態から横へ戻すと、縦位置を保ったまま連続的に内側へ移動でき、余白を増やす方向へは動けません。途中で縦位置が変わっても、横位置を通常範囲へ自動で戻しません。この制限は現在の座標から決め、到達経路を示すフラグは持ちません。狭い画面でも部分段を横から読め、縦位置を固定した横操作だけで本文全体を読めます。記事全体が画面幅より短い場合は先頭側にそろえ、1画面の高さ以下の記事は1段に固定します。縦操作では横位置を、横操作では縦位置を変えません。上下端での自動横誘導は行わず、上下の停止位置にも重なり分の追加余白を設けません。記事の先頭・末尾が基準段の上端・下端にそろう位置で止め、隣の重複だけの部分段はその時点で消えます。

端の部分段では、スクロール面と一緒に動くレールの切り抜きを白い面に合わせます。原点変更の補助座標はCSS変数ではなくdata属性に記録し、数式ツリーへの不要なスタイル再計算を避けます。

同じ論理座標なら、到達経路によらず本文と白い面は同じ配置になります。縦操作が止まった画面を常に同じ配置へ吸着させる処理はありません。Homeは先頭段を左端、Endは末尾段を右端にそろえ、外側に1段分の空白を付けません。Home直後の左移動とEnd直後の右移動は止まります。これらの基準配置は、それまでの経路やズームに左右されません。リサイズ時も本文位置を復元します。

本文の重なりは `createLayout` に0を渡して固定します。過去に保存された重なり設定やCSS変数は参照せず、段組みの切り替え・リサイズ・ページ再読込後も0です。

`src/scripts/column-coordinates.ts` が1/1024 CSS px単位の整数で、唯一の論理座標・移動範囲・部分段の形を計算します。描画と境界判定は同じ座標を使い、描画時だけの吸着や微小量の引き算は使いません。`column-geometry.ts` は有限なブラウザー平面への投影、`column-viewport.ts` はネイティブの小数座標との変換だけを担当します。ブラウザーの観測値をまず同じ1/1024px単位へ変換し、その整数値同士の差分を入力として読みます。投影にも同じ整数化した観測値を使い、浮動小数の差分を後から丸めることで生じていた1単位の揺れを防ぎます。自分で書き込んだ値を論理座標として再解釈しないため、Home／Endの値や操作範囲が丸め誤差で変化しません。ズームによるスクロール領域と座標の丸めの違いはこの境界だけで正規化し、投影側で実際のオフセットを補償します。高さ0の段は幅も含めて完全に切り抜き、細い白い線を残しません。段の本文の translate は `column-geometry.ts` の `devicePixels` で 1/devicePixelRatio 単位に丸めます。段の周期がデバイスピクセルの整数倍にならない倍率（例: 125%で706 CSS px = 882.5デバイスピクセル）では、半端な位置に置いた段の文字を Chromium が再描画せずに動かし、ぼやけて見えたためです。

## スクロールと段の描画

表示枠の高さと位置は CSS の sticky で維持し、縦の切り抜きは共通のスクロール領域、段幅の切り抜きはスクロール面と一緒に動くレールの clip-path で行います。本文は共通のスクロール面を基準に配置するため、通常の縦横スクロールに JS の同期処理は使いません。速度・慣性・数式や表の中のスクロールはブラウザに任せます。wheel / touch ハンドラーは左右キーのアニメーションを中断するためだけに使い、上下端で横位置を補正しません。ネイティブの入力を打ち消す処理は使いません。ブラウザ上の平面は有限な領域とし（大きさは `column-geometry.ts`）、端に近づくと原点とネイティブスクロール位置を同時に組み替えます。

画面外の段は先に作らず、横移動中に左右端で部分的に見える段までを覆う最小限の固定数のスロットを使い回します。全文DOMは元本文1個だけです。元本文を1段の表示と計測に使い、他の段には表示範囲に重なるブロックだけを複製します。`src/scripts/column-fragments.ts` が段落・見出し・リスト・表・折りたたみ・コード図版などの位置を計測し、二分探索で対象を絞ります。画像・フォント・折りたたみ・画面幅などによる再計測時以外は、元本文のレイアウトを読み直しません。各段は上下に少し余裕を持った範囲の断片を用意し、表示中の段では範囲内の断片を再利用し、離れたブロックは削除します。本文の範囲外で紙面が見えない枠は直前の断片を保持して更新せず、再び表示されるときに必要な内容へ更新します。親の `.post`、元の幅・座標、リスト先頭の折りたたまれた余白を保持して組版を合わせます。

元本文のIDとアクセシビリティツリーを保ち、表示断片だけを支援技術とTab移動から除外します。目次やキーボードで操作する対象を含む段には元本文を割り当て、フォーカス位置と表示位置を一致させます。折りたたみは元本文への対応番号を使い、先行する詳細が断片から省かれていても同じ項目を操作します。1段表示・印刷・ページ遷移時には元本文を通常の文書位置へ戻します。段の配置はレールの left と本文ルートの二軸 translate だけで更新し、座標を継承するCSS変数を本文ツリーに流しません。本文の横移動でも left を変更せず、段を再利用する際の本文全体の再レイアウトを避けます。形状と位置は前回適用した値を保持し、CSSOMによる値の文字列表現の違いで同じスタイルを再設定しません。変化していない位置情報はDOMに書き直さず、先頭・末尾で外向きの矢印キーを押しても同じ位置への再スクロールを行いません。ネイティブのスクロール位置はDOMを書き換える前に読み、本文断片を挿入する途中でレイアウトを読み直しません。これにより段を再利用するたびに残存する数式の全要素へスタイル再計算が波及することを避けます。

段の境界をまたいだときに本文の先頭と末尾に合わせてスクロール範囲を広げたり縮めたりします。全画面点の本文位置と横の端数を維持します。末尾付近への目次・ハッシュ移動では、対象が画面右側の段に表示される場合があります。レールと平面で領域外を切り抜き、固定枠自体にはクリップを設定しません（スクロール時に後続の本文まで描画から落ちるため）。元本文を含む表示枠数の上限は「表示幅 / 段の周期を切り上げた数 + 1」で、記事の長さや移動距離に依存しません。先頭・末尾の端数段もこの上限に含めます。通常の横方向の入力は画面幅にかかわらず吸着せず自由にスクロールでき、左右キーでは全段を同時に1段分送れます。縦バー用の幅はブラウザーが確保し、ホイール・タッチ・キー操作も標準の動作を使います。スロット数が変わる場合も元本文と既存の枠を残し、必要な枠だけ追加・削除します。

## キー操作

閲覧者から見たキー操作は `README.md` の「記事の段組み」にあります。

- PageDown / Space: 見えている段数 × Hだけ縦に進む。PageUp / Shift+Spaceは逆方向。
- 左右キー: 減速アニメーション（`src/scripts/column-motion.ts`）で1段分の横移動。連打時は移動先を合成し、逆方向の入力では現在位置から折り返します。ホイール・タッチ・ドラッグ・画面変更・ページ移動で中断します。動きを減らす設定ではアニメーションを省きます。
- 目次・数式参照・URL ハッシュ: 元本文の ID から位置を測り、到達できる候補のうち最短距離へ移動。

## コード・操作要素・制約

n段表示ではコードを段幅で折り返し、折り返した行は行番号の後ろにそろえます。横にスクロールする本文の中に、同じ向きにスクロールするコードを置かないためです。コピーされる内容は変わりません。数式と表は横スクロールのままです。1段表示のコードは折り返しません。

本文の操作要素は折りたたみとコードコピーです。折りたたみは元本文と全スロットで開閉状態を共有し、コードコピーは既存のイベント委譲で動作します。実行型コードやクライアント側の数式レンダラはありません。画像の実寸を計測するため、n段を有効にした記事では元本文の画像を先読みします。

制約: リスト・表・折りたたみなどはブロック全体を保持するため、単一の巨大なブロックではDOM削減幅が小さくなります。JSの更新が止まった状態で準備済みの断片を越えて移動すると、次の描画更新まで空白になる可能性があります。入力速度を制限して防ぐ処理は設けません。読書領域のスクロールバーは仮想平面内の操作用で、記事全体の進捗を表しません。原点の組み替えに応じてつまみの位置も変わります。横バーだけでも先頭・末尾の部分段まで到達でき、Home / Endで基準配置へ戻れます。ブラウザのページ内検索では表示断片もヒットする場合があります。別の段をまたぐ文字選択・コピーでは、各段が独立した本文断片であることが影響します。現在のサイトはライトテーマで、n段表示も既存の本文色を使います。

## 背景の一覧と紙面

一覧はヘッダーの下にある領域自身をスクロールし、記事と共通の太さ・色・矢印を持つ標準バーを使います。スクロール位置は一覧領域から保存・復元します。`ArticleIndex.astro` を共通レイアウトに置き、`transition:persist` で記事への遷移・一覧への復帰・記事間移動でも同じDOMを保持します。1段・n段とも、開く直前の一覧位置で背景を固定し、透かしとぼかしを重ねます。背景の一覧は `inert` と `aria-hidden` で操作対象から外し、閉じたときは一覧位置と該当カードへのフォーカスを復元します。遷移先HTMLの取得は通常のClientRouterに任せます。

紙面の色・影・丸角は `--note-surface`・`--note-shadow`・`--note-radius` で共通化しています。n段は実際の本文先頭の上2隅、末尾の下2隅だけを丸め、続く端は直角にします。段間や紙面外クリックで一覧へ戻り、選択解除・ドラッグ・ネイティブバー操作では閉じません。上部目次の左右には正三角形のボタンを置き、見出し行の中央にそろえます。クリック・長押し・キーボードで目次だけを動かします。

## 保存と復元

ブラウザー履歴の項目ごとの読書位置と折りたたみの開閉状態は、ページを離れるときに `sessionStorage` に保存します（`src/scripts/reading-history.ts`。件数の上限も同じファイル）。復帰時は、開閉状態を本文の計測と位置復元より先に適用します。1段・n段の選択は `localStorage` に保存し、未選択と不正な値の扱いは `src/scripts/column-preference.ts` にあります。

`?columns=` の指定で開いた後に段組みを切り替えても、URLは書き換えません。Astroのルーターは、クエリが変わると戻る・進むを別ページへの遷移として扱うためです。代わりに、切り替え後の段組みをその履歴項目に記録します。`?columns=` 付きのURLでも、`rel="canonical"` はクエリなしのURLです（`src/layouts/Layout.astro`）。
