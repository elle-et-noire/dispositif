Eratosthenesの篩

特に工夫をしなければ以下のような実装になるはず。mがp^2から動き始めるのは、p^2より小さい合成数はpより小さい素数ですでに割られているはずだからである。

2の倍数判定を省略すると以下のようになる。flags[j]に2j+1が素数かどうかのフラグが格納されている。(2j+1)^2 == 2(2j*(j+1)) + 1なので、mは2j*(j+1)から動き始める。

2,3,5の倍数まであらかじめ除いておくと、30でわった余りが1,7,11,13,17,19,23,29の8通りだけ気にすればよい（参考）。28 は十分整数型で表せるので、各数が合成数かどうかのフラグをbit列として整数型に格納して処理できる（つまり30でわった商それぞれにUInt8型の値が1つずつ対応する。例えば[0b00001000, 0b01000000]は13と53にフラグが立っている）。

  1. 篩い始めの位置
    素数 𝑝 で篩にかけていく際、

𝑝=30𝑞+𝑟𝑗,𝑟𝑗∈{1,7,11,13,17,19,23,29} に対して篩い始めの 𝑝2 が格納されている場所は 𝑝2 =30(30𝑞2 +2𝑞𝑟𝑗 +⌊𝑟2𝑗/30⌋) +(𝑟2𝑗mod 30) から30q^2 + 2q * r[j] + r[j]^2 ÷ 30番目のUInt8のr[j]^2 % 30ビット目と分かる。

  1. 篩う処理
    素数 𝑝 =30𝑞 +𝑟𝑗 に 𝑛 =30𝑞𝑛 +𝑟𝑘 をかけた合成数 𝑝𝑛 を篩うことを考える。𝑝𝑛 =30𝑞𝑝𝑛 +(𝑟𝑗𝑟𝑘mod 30) となる（ただし 𝑞𝑝𝑛 =⌊𝑝𝑛/30⌋）ので、flags[q_pn]のr[j] * r[k] % 30に対応するビットを0にすればよい（r[j] * r[k] % 30が再びrに含まれることは ℤ30 の乗法群の構造が保証してくれる）。r[j] * r[k] % 30を 8 ×8 行列r_rr[j,k]で取り出せるようにしておくと同じ計算を何度もせずに済む。

  2. 次に篩う位置
    𝑝𝑛 を篩ったら次は 𝑝𝑛′ を篩いたい。ここで 𝑛′ =30𝑞𝑛 +𝑟𝑘+1 は 30𝑞 +{1,7,11,13,17,19,23,29} で表される整数で 𝑛 の次に小さいものである（ただし 𝑟𝑘+1 ∈{7,11,13,17,19,23,29,31}）。そのためには 𝑞𝑝𝑛′ =⌊𝑝𝑛′/30⌋ を得る必要があるが、これは差分を計算するとよい：

⌊𝑝𝑛′/30⌋−⌊𝑝𝑛/30⌋=⌊(30𝑞+𝑟𝑗)(30𝑞𝑛+𝑟𝑘+1)30⌋−⌊(30𝑞+𝑟𝑗)(30𝑞𝑛+𝑟𝑘)30⌋=𝑞(𝑟𝑘+1−𝑟𝑘)+⌊𝑟𝑗𝑟𝑘+130⌋−⌊𝑟𝑗𝑟𝑘30⌋. 𝑟𝑘+1 −𝑟𝑘 をdr[k]に、⌊𝑟𝑗𝑟𝑘+130⌋ −⌊𝑟𝑗𝑟𝑘30⌋ をdqrr[j,k]にそれぞれ格納しておくとやはり計算を節約できる。ビット位置についてはk = (k+1) % 8でよい。

以上の内容をコードに落とすと以下のようになる（Juliaが1-indexedであるため上の疑似コードからインデックスが若干ずれる）。またr,dr,dqrr,r_rrは長さが決まっていて頻繁にアクセスするのでStaticArrays.SArrayとして定義することで大幅に高速化できる。

Ricciスカラーの計算

計量 𝑔𝑖𝑗 が与えられれば定義に従ってChristoffel記号

Γ𝑖𝑗𝑘=12𝑔𝑖𝑙(𝑔𝑙𝑗,𝑘+𝑔𝑘𝑙,𝑗−𝑔𝑗𝑘,𝑙) が得られる（手計算の場合は作用 𝑆 =∫d𝑡𝑔𝑖𝑗˙𝑥𝑖˙𝑥𝑗 から測地線方程式を導き、その係数からChristoffel記号を読み取る方が幾分か楽 参考）。以下定義を列挙する。

  • Riemann曲率テンソル : 𝑅𝑖𝑗𝑘𝑙 =𝜕𝑘Γ𝑖𝑗𝑙 −𝜕𝑙Γ𝑖𝑗𝑘 +Γ𝑖𝑚𝑘Γ𝑚𝑗𝑙 −Γ𝑖𝑚𝑙Γ𝑚𝑗𝑘
  • Ricciテンソル : 𝑅𝑖𝑗 =𝑅𝑘𝑖𝑘𝑗
  • Ricciスカラー : 𝑆 =tr⁡𝑅

Symbolics.jlを使えば形式的な計算が可能になる。
